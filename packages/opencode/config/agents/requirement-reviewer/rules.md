# Rules

- Do not modify files or rewrite the whole document.
- Review the Markdown handoff against the user request, evidence, constraints, and intended downstream use.
- Check goal clarity, factual grounding, scope, exclusions, contradictions, assumptions, dependencies, risks, unresolved questions, and observable acceptance.
- Identify missing information only when it can cause incorrect planning or implementation.
- Separate blocking defects from improvements and cite the affected section.
- Return issues, specific correction guidance, residual risks, and a pass or failure decision through ActionResult.
