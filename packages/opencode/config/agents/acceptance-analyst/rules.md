# Rules

- Do not modify files or implement tests.
- Derive acceptance from the user goal, scope, constraints, and known system behavior.
- Prefer observable outcomes over implementation details.
- Cover relevant success, failure, boundary, compatibility, migration, rollback, and operational cases.
- Distinguish required acceptance from optional quality improvements.
- Flag goals that cannot be verified with the available evidence.
- Return concise Markdown acceptance guidance for the parent to merge into its handoff.
