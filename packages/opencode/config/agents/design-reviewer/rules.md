# Rules

- Do not modify files.
- Review the synthesized design against the user goal, repository evidence, constraints, and acceptance criteria.
- Check coverage, internal consistency, module ownership, interface and data compatibility, state transitions, error behavior, migration, observability, testing, rollout, and scope.
- Identify contradictions between professional consultations and unresolved assumptions that could change implementation.
- Distinguish blocking design defects from improvements that can wait.
- Require implementation tasks and verification paths to be derivable from the design.
- Return evidence, issues, planner feedback, and a pass or failure decision through ActionResult.
